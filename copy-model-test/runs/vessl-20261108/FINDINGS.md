# VESSL 4비트 모델 재실험 — 판단과 한계

**기존 3종의 IT/Instruct 모델을 서버에 다운로드해 12개 실제 응답을 확보했습니다.**
상품은 랑드샤 베스트 티 4종 세트, 기간은 12월 한 달이며 연도는 미정입니다.
크리스마스·가을·송년·신년 각각 hero 1구좌를 시험했습니다. 입력은 이전 소형 CPU 실험과
해시가 같으며, 주제별 최신 오설록 메인 배너와 기존 오설록 발췌문 2개를 전달했습니다.

## 실행 결과

| 모델 | 정확한 Ollama 태그 | 실제 응답 | 기본 규칙 통과 | 코드펜스 없는 JSON |
|---|---|---:|---:|---:|
| Gemma 3n E4B IT | `gemma3n:e4b-it-q4_K_M` | 4/4 | 3/4 | 0/4 |
| Gemma 3 12B IT | `gemma3:12b-it-q4_K_M` | 4/4 | 4/4 | 0/4 |
| Qwen3-VL 4B Instruct | `qwen3-vl:4b-instruct-q4_K_M` | 4/4 | 3/4 | 4/4 |
| 합계 | | 12/12 | 10/12 | 4/12 |

각 셀은 주제별 한 번의 응답입니다. 기본 검사는 상품명·기간·미확정 숫자/혜택·예약 흐름·
글자 수·주제/구좌·출처 ID 등을 확인합니다. 검사 통과는 문체 승인이나 의미적으로 충분한
출처 활용을 보증하지 않습니다. 두 Gemma 모델의 코드펜스를 벗겨 JSON으로 읽은 경우에도
원문을 보존하고 `strict_json=false`를 기록했습니다.

## 실제로 확인한 문제

- **Gemma 3n 송년:** 제목에 ‘2023년’을 만들었습니다. 입력의 연도는 미정이므로
  `conflicting_schedule_claim`, `unsupported_numeric_claim`으로 거절했습니다.
- **Qwen Instruct 가을:** CTA가 ‘지금 예약’입니다. 예약 판매나 예약 경로를 입력하지 않았으므로
  `unconfirmed_purchase_flow`로 거절했습니다. 예약 여부를 사실 입력으로 확정하기 전에는
  해당 버튼 문구를 사용하면 안 됩니다.
- **Gemma 3 12B:** 네 건 모두 기본 규칙은 통과했습니다. 다만 가을 CTA ‘따뜻한 티 한 잔’은
  명확한 동작을 안내하는 버튼 문구로 다듬을 여지가 있습니다.
- **Qwen Instruct:** JSON 형식은 가장 안정적이지만 신년의 ‘최고의 선물’처럼 실험용 차분한 문체에
  비해 강한 표현이 있고, 참고 이유가 선착순·쿠폰 형식을 반복해서 설명하는 경향이 있습니다.
  소비자 카피가 실제 미확정 쿠폰을 약속한 것은 아니지만, 구체적으로 어떤 문장 구조를
  활용했는지에 대한 설명은 담당자가 다시 확인하는 편이 좋습니다.
- **참고 이유 대조:** Gemma 3 12B가 인용한 ‘조용히 다가온 연말의 페이지’는 실제
  `osulloc-002#s01` 입력에 있습니다. 원문에 없는 표현으로 잘못 판정하지 않았습니다.
  일반적인 출처 인용 검사도 추가했으며, 직접 인용문이 입력 발췌문과 다르면 검토 경고를 냅니다.

예를 들어 Gemma 3 12B의 크리스마스 제목은 ‘소중한 순간, 티로 축복하세요’,
Qwen Instruct의 송년 제목은 ‘연말의 감사, 한 잔으로 전해’였습니다.
전체 제목·설명·버튼·기간·출처는 [REPORT.md](REPORT.md)와 [REPORT.html](REPORT.html)에 있습니다.
이 문서의 판단은 실제 응답에 대한 정성 검토이며 별도의 현업 평가 점수를 만든 것이 아닙니다.

## 다음 비교의 우선 후보

이번 네 주제의 기본 사실 준수만 보면 **Gemma 3 12B를 우선 후보**로 검토할 수 있습니다.
Qwen Instruct는 JSON 구조가 안정적이므로 예약·할인 같은 미확정 흐름을 차단하는 검사를
함께 적용해 비교할 만합니다. 4개 샘플만으로 최종 모델을 확정하거나 노트북의 품질/속도를
보증하지는 않습니다. 사내 승인 문구와 실제 기기에서 반복 비교가 필요합니다.

## 서버와 저장

VESSL `hyerin-vulkan-50g`의 RTX 3090 환경에서 Ollama 0.40.15를 사용했습니다.
워크스페이스에는 GPU가 2개 있지만 이 실험은 `CUDA_VISIBLE_DEVICES=0`으로 한 장을 사용했습니다.
모든 응답에서 `/api/ps`의 `size_vram > 0`을 확인했습니다. 모델마다 실제 GPU 배치를 JSON에 남겼습니다.

지정한 세 모델의 배포 파일 크기는 합계 **21,269,847,235바이트, 약 21.27GB**입니다.
서버 `/root/osulloc-copy-test/models/`에 보관하며 Git에 가중치를 넣지 않습니다.
설치·다운로드는 서버의 전용 작업 폴더에서 수행했고 기존 프로젝트와 HF 캐시는 보존했습니다.
세 모델의 생성이 끝난 뒤 모두 GPU 메모리에서 내렸습니다. 워크스페이스와 로컬 Ollama 서비스는
다음 실행에 쓸 수 있도록 실행 상태로 두었습니다.

소형 CPU 실험이나 이전 BF16 공개 데모와 정밀도·실행기·하드웨어가 다릅니다.
GPU 시간과 CPU/네트워크 대기 포함 시간을 동일 조건 성능 순위로 비교하지 않습니다.
첫 요청의 벽시계 시간에는 모델 로드가 포함될 수 있어 Ollama의 `load_duration`,
`prompt_eval_duration`, `eval_duration`을 따로 저장했습니다.

## 태그 확인 중 제외한 시도

초기 기본 태그 `qwen3-vl:4b`는 Thinking 변형을 가리켰고, 4회 모두 최종 문구가 비었습니다.
요청된 Instruct 결과로 집계하지 않고 `../vessl-tag-check-20261108/`에 기록했습니다.
정확한 Instruct 태그로 다시 다운로드해 위 표의 네 응답을 얻었습니다.
기본 태그를 검증하지 않은 초기 선택을 수정했고, 실행기에 Thinking 혼입을 막는 검사를 추가했습니다.
해당 미사용 Thinking 가중치는 이 작업 폴더에서 제거했으며 진단 JSON은 보존했습니다.

원문을 사람이 수정하거나 실패를 성공 문구로 대체하지 않았습니다.
